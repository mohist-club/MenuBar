## 文档约定

- **代码是行为的最终事实来源**；文档与代码冲突时，应在同一个改动中修正文档。
- 功能改动至少检查 README、架构说明、工程标准和发布清单是否受影响。
- 重要架构决策应记录“为什么”，不能只记录最终做法。
- 面向用户的说明按每次 Release 检查；工程文档至少每季度复核一次。
- 当前负责人：Wayne；公开贡献通过 GitHub Issue / Pull Request 讨论。
